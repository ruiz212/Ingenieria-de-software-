# Implementación WhatsApp — ejecución por Codex

Autorizada por el usuario el 4 de noviembre de 2026, sobre la revisión previa.
Se reutiliza la rama de trabajo actual; se preservan cambios existentes de autenticación.

1. Persistencia: migración aditiva SQL Server, sesiones con token privado, inbox deduplicado,
   outbox con reintentos y auditoría de herramientas. Roles explícitos para worker y panel.
2. Dominio: políticas deterministas, herramientas de catálogo, recomendaciones generales,
   cotizaciones propias del canal, seguimiento por código privado y atención humana.
   Pruebas primero: identidad no elegible por LLM, confirmación, fechas, duplicados y pausa.
3. Agente: adaptador Gemini, ejecución limitada de herramientas, memoria acotada y fallback.
4. Transporte: Neonize opcional en proceso independiente, singleton SQL, QR privado,
   recepción validada de imágenes, reintentos y apagado limpio.
5. Integración: POS/KDS encolan dentro de su transacción; panel accesible a gerencia,
   con CSRF, historial, respuesta humana, pausa y configuración global.
6. Validar pruebas unitarias sin SQL, regresiones y revisión final; documentar instalación.

Decisiones: teléfono no vincula historial antiguo; solo token de la sesión WhatsApp autoriza
cotizaciones del canal. Seguimiento exige el código privado existente. IA no registra pagos
ni emite facturas. Consentimiento explícito para avisos proactivos. Bot apagado inicialmente.
No ejecutar migraciones ni conectar una cuenta real durante la implementación.

Estado: implementación local terminada. Integrador y programador: Codex; sin delegación.

Verificación final: 441 pruebas aprobadas y 104 omitidas (73,93 s), compilación Python,
46 paquetes CSS verificados, diff sin errores de espacios. Panel renderizado con datos
sintéticos y comprobado en Chrome a 390/1440 px, sin desbordamiento. Neonize 0.10.0
instalado e importado en venv aislado con Python 3.14.4; pip check sin incompatibilidades.
Revisión propia: límites SQL, identidad, carreras de handoff/fotos, precio de confirmación,
idempotencia y preservación de cambios previos. Correcciones verificadas con la suite.

Pendiente externo: ejecutar y verificar la migración en SQL Server QA, permisos efectivos,
configurar el proveedor y vincular una cuenta de prueba. No se hicieron migraciones,
