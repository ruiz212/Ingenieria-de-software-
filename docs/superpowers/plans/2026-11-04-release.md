# Integración en main y despliegue

Autorizado por el usuario: subir todos los cambios, hacer merge con main y desplegar.
Programador e integrador: Codex. Reutilizar checkout y rama existentes, sin delegación.

1. Revisar todo el estado pendiente, historial remoto y flujo de Azure. Preservar los
   cambios previos de autenticación y documentación, incluidos en «todos los cambios».
2. Corregir las dos regresiones de ciclo de vida/monitorización antes del merge,
   probándolas primero en rojo y después en verde. Inferencia en un solo executor;
   heartbeat y envíos independientes, sin compartir conexiones SQL entre hilos.
3. Empaquetar únicamente archivos de ejecución para Azure. Agregar prueba del ZIP,
   dependencias del worker y una puerta de pruebas en CI antes del despliegue.
4. Suite completa sin base operativa, CSS, revisión de credenciales y dependencias
   en entorno aislado. No migrar SQL ni vincular WhatsApp como parte de esta entrega.
5. Commit, integrar el main remoto, probar el árbol resultante, subir rama y main sin
   force push. Observar GitHub Actions y comprobar HTTP de la aplicación desplegada.

Preflight: origin/main contiene siete commits de merge posteriores a la rama actual,
sin diferencias de árbol. La cuenta configurada tiene permisos de push y el workflow
de producción dispone del secreto de publicación. No hay protección de rama main.
Se revisan solo nombres/metadatos de credenciales; sus valores no se publican.

Validación local previa: 459 pruebas aprobadas y 104 omitidas; 46 paquetes CSS
verificados. Dos pruebas de worker y una de empaquetado fallaron antes de corregir.
El Python global contiene paquetes Google ajenos al proyecto incompatibles con protobuf;
se comprueba el conjunto de dependencias del proyecto en un entorno aislado para evitar
atribuir esos conflictos globales a la entrega.

Validación en GitHub: las dependencias se instalaron correctamente en Linux. La puerta
de pruebas detectó dos fixtures históricas que inventaban una conexión local de Windows
y contaminaban TEST_DB_CONNECTION_STRING al fallar su inicialización. Se eliminaron
esos destinos implícitos y se agregaron dos pruebas de regresión que exigen omitir SQL
si no hay conexión QA explícita. Resultado local final sin SQL: 397 aprobadas y 168
omitidas. El descenso de aprobadas corresponde a pruebas SQL que antes se conectaban
por defecto a una QA local, no a eliminación de pruebas. Las omitidas no se certifican.
GitHub recibe anotaciones JUnit concisas para diagnosticar fallos antes de publicar.
